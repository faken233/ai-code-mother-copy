## 6. 五条不变量（改代码前必须知道）

1. **只有 `lib/query.js` 能拼 SQL**；列名/表名只来自 `schema.json`，值只走 `?`。
2. **归属条件由 `query.scope()` 注入**，业务代码没有"忘记加 user_id"的入口。
3. **应用端口用 `APP_PORT`**，`PORT` 归沙箱文件服务（8080），两者不能重名。
4. **前端 API 基址按当前文档路径推导**（`resolveApiBase()`），禁止写死 `/api` 或主机端口。
5. **平台文件 AI 不可写**：`AppTemplateService.PLATFORM_OWNED` 是唯一清单，写工具/覆盖安装/静态扫描共用它。

## 7. 本会话踩过的坑（别重复）

| 坑 | 症状 | 结论 |
|---|---|---|
| 沙箱镜像烤死 `http_proxy=host.docker.internal:7897` | 容器内 npm 超时 | 用 `sh -c "unset http_proxy...; npm i --registry=npmmirror"`；长期应把 ENV 从镜像里去掉 |
| 沙箱命令白名单无 `env` | `命令不被允许: env` | 用 `sh -c` 包一层，别改镜像 |
| Spring Boot 3 `PATH_WITHIN_HANDLER_MAPPING_ATTRIBUTE` 失效 | 经代理取 JS 返回 index.html | 从 `RequestURI` 剥前缀 |
| `RestTemplate` 默认对 4xx 抛异常 | 越权 404 变 502 | 透传用 `hasError=false` 的 handler |
| 写工具白名单被 `./` 绕过 | `client/src/./api.js` 覆盖平台文件 | 用 `Paths.normalize()` 折叠 `.`/`..` |
| 校验器扫描平台文件 | 构建连续失败（注释里的 `/api/preview/`） | 扫描跳过 `PLATFORM_OWNED` |
| AI 写完直接调 exit 跳过构建 | 任务成功但没有 `public/dist` | 执行器兜底构建，失败即任务失败 |
| shell 变量紧跟中文 | `unbound variable` | 脚本统一 `${VAR}` |
| `docker exec` 不带 `-i` | heredoc 被静默丢弃，建账号"成功"但账号不存在 | 幂等初始化必须**回读校验** |

## 8. 后续改造点（按确认的顺序）

### P1 · accessCode 短链 + 独立 proxy（下一步）

- [ ] 新建 `proxy/` 模块（Spring Boot WebFlux），`WebClient` **流式**反代（不能用 RestTemplate，会缓冲断流）
- [ ] `GET/POST /{accessCode}/**`：剥前缀 → 转发沙箱应用端口；`READY` 才转发，`STARTING`→503，不存在→404
- [ ] `app_access_route` 表（`access_code/app_id/kind/sandbox_host/port/status/expire_at/updated_at`）+ `sql/` 建表
- [ ] `accessCode` 复用 `deployKey`，**应用创建或首次预览时分配**并落库（现在 `deployKey` 只在部署时生成）
- [ ] 主服务写路由（PREVIEW/DEPLOY），proxy 只读 + 本地缓存/Redis
- [ ] `previewApp` 返回 `{proxy-host}/{accessCode}/`；`deployApp` 原子切 PREVIEW→DEPLOY
- [ ] 下线 `PreviewProxyController` 的透传职责（保留旧格式分支）
- [ ] 端口不再发布（proxy 走容器网络）或 `-p 127.0.0.1::3000` 随机 + `docker port` 回读
- [ ] 验收：`curl -N` 经 proxy 收 SSE 不断流；两个 accessCode 指向不同容器；主服务重启链接不断

### P2 · 生命周期

- [ ] 容器 `--restart unless-stopped`；容器 label（`app.id`、`kind`）
- [ ] PREVIEW 路由 TTL（24h）→ 到期 `stopContainer` + 删路由
- [ ] 应用删除时回收容器与库（现在 `stopContainer` 只被 `PreviewService` 调到）
- [ ] 定时 reconcile：任务结束/超时/孤儿容器回收
- [ ] 修 `GenTaskMapper#updateTimeoutTasks` 只扫 `status='running'` 的漏洞（`sandbox_building` 永不超时）
- [ ] 应用进程崩溃后成僵尸（PID1 是 node，不 reap）→ 可换 tini 或 reconcile 重启
- [ ] 验收：连跑 20 个应用后 `docker ps` 数量收敛

### P3 · 技术债

- [ ] 端口取模 `appId%1000` → 动态分配；每应用 3 个宿主端口（8081 是旧格式占位）→ 收敛
- [ ] 依赖预热（`templates/node-unified/.cache/node_modules`）→ 省掉每次 npm install 的 10s
- [ ] 生成失败修复循环：构建失败把错误回灌 AI 再修一轮（现在直接任务失败）
- [ ] `deployApp` 语义重写（现在仍是 `mvn package` + 静态复制，与一体化形态不符）
- [ ] 下载过滤核对（`node_modules`/`public/dist` 已排除，需确认 `client`/`schema.json` 保留）
- [ ] 旧数据兼容：旧格式 `fullstack_*`（Vue+SpringBoot）继续走旧链路，需明确迁移/下线策略
- [ ] 把 `code-sandbox` 镜像里的 `http_proxy` ENV 清掉（运行时不应该带代理）

### 生成侧遗留

- [ ] 一次通过率统计：用固定 3 个业务（待办/记账/留言板）各跑 3 次，统计 build 通过率
- [ ] prompt 里补：列表分页、空状态、错误提示的最小要求（现在靠 AI 自觉）
- [ ] **`routes/custom.js` 目前完全没被加载**（`server.js` 没有 require 它），prompt 里却允许 AI 写；`ctx.db.aggregate` 也未实现。要么补加载器，要么从 prompt 里删掉这个逃生舱
